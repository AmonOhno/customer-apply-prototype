# 取引先マスタ（表形式マスタ保守＋承認ワークフロー）

取引先マスタを Excel のような表で編集し、変更を **変更セット単位** で申請・承認するプロトタイプです。
セル・項目（カラム）・行それぞれに業務上のプロパティ（変更ステータス、閲覧・編集権限、必須、承認要否、機密区分など）を持たせています。

> データはデモ用の架空のものです。保存先はブラウザの localStorage のみで、サーバーはありません。

## 主な機能

| 区分 | 内容 |
| --- | --- |
| 表編集 | ダブルクリック／Enter／直接入力で編集、矢印・Tab 移動、ドラッグ・Shift+クリックで範囲選択、列見出し・行番号クリックで列／行選択 |
| 一括編集 | 範囲に一括入力（ダイアログ、または入力後 **Ctrl+Enter**）、文字列置換、下へコピー（**Ctrl+D**）、クリア（Delete）、Excel との TSV コピー＆貼り付け（1セル→範囲全体、約数サイズは繰り返し） |
| クエリ | 表に表示するレコード（行）とカラム（項目）を切り替える定義。行条件（セル状態・エラー・最終更新日時・項目の確定値）、表示項目（全項目／指定項目／変更のある項目）、並び順を持つ。取引先コード・取引先名は常に表示。検索語と併用でき、各クエリの該当件数をボタンに表示 |
| セルの状態 | 確定／編集中／新規（未申請）／承認待ち（ロック）／差戻し／承認済（24時間以内）を色と左端の帯で表示。入力エラーは赤枠 |
| セルコメント | 変更・新規登録したセルに申請の意図をコメントとして記載（右パネル・申請ダイアログ・一括編集で入力）。コメントのあるセルは右上に三角マーク。承認者はワークフロー画面と右パネルで確認でき、承認後も変更履歴に残る。差戻し・取り下げ時は下書きに戻る。閲覧権限のない項目のコメントは表示しない |
| 項目のプロパティ | ロール別の閲覧・編集権限、必須、形式（正規表現）、文字数、承認要否、登録後変更不可、機密。閲覧権限のない項目は列として表示しない |
| 閲覧範囲（行） | マスタ管理者が行の条件（項目の確定値が「いずれかに一致／いずれにも一致しない／空／空でない」）を定義し、閲覧できるロールに紐づける。利用者は自分のロールに紐づくいずれかの閲覧範囲に該当する行だけを閲覧・編集できる。自分の新規行・自分が申請中の新規行は常に表示 |
| ワークフロー | 下書き → 申請（件名・理由）→ 承認／差戻し（理由必須）／取り下げ。承認不要の項目は申請時に即時反映 |
| 統制 | 申請者本人は承認不可（職務分掌）、承認者は編集権限を持てない、申請後に確定値が変わったセルは承認不可（競合検知）、コード重複チェック |
| 監査 | セル単位の変更履歴（日時・申請者・変更前後・変更セット） |

## ロール（画面右上で切り替え）

| ユーザー | ロール | できること |
| --- | --- | --- |
| 田中 美咲 | 営業担当 | 基本情報の編集・新規登録の申請。振込先口座・与信限度額は閲覧不可（列が表示されない）。閲覧範囲は取引中の取引先のみ |
| 佐藤 健 | 経理担当 | 支払条件・インボイス番号・口座・与信の編集・申請 |
| 鈴木 部長 | 承認者 | すべて閲覧、承認・差戻し（編集は不可） |
| 高橋 管理者 | マスタ管理者 | すべての編集・承認（自分の申請以外）・項目設定・閲覧範囲の設定 |

## クエリ（初期セット）

| クエリ | 行 | 項目 | 業務上の用途 |
| --- | --- | --- | --- |
| すべて | 全件 | 全項目 | 通常の保守 |
| 変更箇所のみ | 編集中・新規・承認待ち・差戻しのセルがある行 | 変更のある項目のみ（新規行は入力済み・エラーの項目） | 申請前の確認、変更内容の把握 |
| 直近1ヶ月に更新 | 最終更新日時が1ヶ月以内（新しい順） | 全項目 | 最近の変更の確認・監査 |
| 承認待ち | 承認待ちの変更がある行 | 申請中の項目のみ | 承認者の確認 |
| 要対応（差戻し・エラー） | 差戻し・入力エラーのセルがある行 | 全項目 | 申請者の手戻り対応 |
| インボイス番号未登録 | 取引中の仕入先で、適格請求書発行事業者番号が確定値で空 | 区分・法人番号・インボイス番号など | インボイス制度対応の確認 |
| 支払・与信項目 | 全件 | 支払条件・口座・与信など経理項目 | 経理の定期確認 |
| 1年以上未更新 | 取引中で最終更新から1年以上（古い順） | 全項目 | 登録内容の定期棚卸し |

項目の確定値で絞るクエリは下書きを見ないため、修正を入力しても申請・承認されるまで行は表示されたままです。閲覧権限のない項目の条件には該当しません（値を推測させないため）。

## 開発

```bash
npm install
npm run dev          # 開発サーバー
npm test             # ドメイン層のテスト（Node 22.18+ の型除去で実行、追加依存なし）
npm run build        # 型チェック＋本番ビルド（dist/）
npm run build:single # CDN版Reactを使う1ファイルHTML（dist-single/index.html）
```

### 公開（GitHub Pages）

`main` にプッシュすると `.github/workflows/deploy-pages.yml` がテスト・ビルドして https://amonohno.github.io/customer-apply-prototype/ に公開します。初回のみリポジトリの Settings → Pages → Source を「GitHub Actions」にしてください。

## 構成

```
src/
  domain/            画面に依存しない業務ロジック（テスト対象）
    types.ts         データモデル（カラム定義・下書き・変更セット・履歴）
    columns.ts       取引先マスタの項目定義と権限の初期値
    permissions.ts   閲覧・編集・承認の判定、セルのロック理由
    validation.ts    型変換・入力チェック
    reducer.ts       編集・申請・承認・差戻し・取り下げ・項目設定の状態遷移
    grid.ts          表示用の行モデルとセル状態の算出
    queries.ts       クエリ（表示する行・項目の条件）の定義と適用
    bulk.ts          TSV 解析、貼り付け・下へコピー・置換の計画
  components/        React コンポーネント（表、一括編集、申請、ワークフロー、項目設定、プロパティパネル）
  store.ts           useReducer＋localStorage 永続化
```

状態遷移はすべて `domain/reducer.ts` の純粋関数に集約しているため、API／DB を付ける場合は reducer の各アクションをサーバー側のユースケースに移す形で拡張できます。
