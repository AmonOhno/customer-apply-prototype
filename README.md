# 取引先マスタ（表形式マスタ保守＋承認ワークフロー）

取引先マスタを Excel のような表で編集し、変更を **変更セット単位** で申請・承認するプロトタイプです。
セル・項目（カラム）・行それぞれに業務上のプロパティ（変更ステータス、閲覧・編集権限、必須、承認要否、機密区分など）を持たせています。

> データはデモ用の架空のものです。保存先はブラウザの localStorage のみで、サーバーはありません。

## 主な機能

| 区分 | 内容 |
| --- | --- |
| 表編集 | ダブルクリック／Enter／直接入力で編集、矢印・Tab 移動、ドラッグ・Shift+クリックで範囲選択、列見出し・行番号クリックで列／行選択 |
| 一括編集 | 範囲に一括入力（ダイアログ、または入力後 **Ctrl+Enter**）、文字列置換、下へコピー（**Ctrl+D**）、クリア（Delete）、Excel との TSV コピー＆貼り付け（1セル→範囲全体、約数サイズは繰り返し） |
| セルの状態 | 確定／編集中／新規（未申請）／承認待ち（ロック）／差戻し／承認済（24時間以内）を色と左端の帯で表示。入力エラーは赤枠 |
| 項目のプロパティ | ロール別の閲覧・編集権限、必須、形式（正規表現）、文字数、承認要否、登録後変更不可、機密。閲覧権限のない項目はマスク表示し、コピーにも値を含めない |
| ワークフロー | 下書き → 申請（件名・理由）→ 承認／差戻し（理由必須）／取り下げ。承認不要の項目は申請時に即時反映 |
| 統制 | 申請者本人は承認不可（職務分掌）、承認者は編集権限を持てない、申請後に確定値が変わったセルは承認不可（競合検知）、コード重複チェック |
| 監査 | セル単位の変更履歴（日時・申請者・変更前後・変更セット） |

## ロール（画面右上で切り替え）

| ユーザー | ロール | できること |
| --- | --- | --- |
| 田中 美咲 | 営業担当 | 基本情報の編集・新規登録の申請。振込先口座・与信限度額は閲覧不可 |
| 佐藤 健 | 経理担当 | 支払条件・インボイス番号・口座・与信の編集・申請 |
| 鈴木 部長 | 承認者 | すべて閲覧、承認・差戻し（編集は不可） |
| 高橋 管理者 | マスタ管理者 | すべての編集・承認（自分の申請以外）・項目設定 |

## 開発

```bash
npm install
npm run dev          # 開発サーバー
npm test             # ドメイン層のテスト（Node 22.18+ の型除去で実行、追加依存なし）
npm run build        # 型チェック＋本番ビルド（dist/）
npm run build:single # CDN版Reactを使う1ファイルHTML（dist-single/index.html）
```

## 構成

```
src/
  domain/            画面に依存しない業務ロジック（テスト対象）
    types.ts         データモデル（カラム定義・下書き・変更セット・履歴）
    columns.ts       取引先マスタの項目定義と権限の初期値
    permissions.ts   閲覧・編集・承認の判定、セルのロック理由
    validation.ts    型変換・入力チェック
    reducer.ts       編集・申請・承認・差戻し・取り下げ・項目設定の状態遷移
    grid.ts          表示用の行モデルとセル状態の算出
    bulk.ts          TSV 解析、貼り付け・下へコピー・置換の計画
  components/        React コンポーネント（表、一括編集、申請、ワークフロー、項目設定、プロパティパネル）
  store.ts           useReducer＋localStorage 永続化
```

状態遷移はすべて `domain/reducer.ts` の純粋関数に集約しているため、API／DB を付ける場合は reducer の各アクションをサーバー側のユースケースに移す形で拡張できます。
